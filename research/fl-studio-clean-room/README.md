# FL Studio — чистая комната: исследование интерфейса и рабочих процессов

Папка: `research/fl-studio-clean-room/` • Дата: 2026-10-20 • Проект: VibeStudio

## 1. Цели

Восстановить **наблюдаемое поведение** FL Studio (паттерновой DAW Image-Line) на уровне, достаточном, чтобы спроектировать собственный интерфейс DAW с аналогичной логикой работы:

- как устроено рабочее пространство и его главные окна;
- как пользователь выполняет базовые операции (паттерн → мелодия → аранжировка → микс → экспорт);
- как окна и компоненты связаны между собой (данные, фокус, маршрутизация);
- какие правила взаимодействия (мышь, клавиатура, контекстные меню) делают workflow «быстрым».

Исследование — **метод чистой комнаты**: мы описываем только видимое поведение из публичных источников и формулируем независимые спецификации. Мы **не** копируем исходный код, графические ресурсы, брендинг или закрытые реализации FL Studio и не пытаемся угадывать внутреннее устройство её кода.

## 2. Методика

1. **Официальная документация.** Полностью прочитаны ключевые страницы онлайн-мануала Image-Line (`image-line.com/fl-studio-learning/fl-studio-online-manual/html/*.htm`) — мануал соответствует актуальной версии FL Studio 21.3/2024–2025 (упоминания FL Cloud, Gopher, 500 insert-треков, Elastique e3), с вкраплениями текстов эпохи FL 20. Дополнительно прочитан официальный «Getting Started Manual» (PDF, 88 стр., издание FL 20) — целиком, с извлечением текста.
2. **Видео.** Видео невозможно было просмотреть как видео; для одного официального часового туториала (канал FL Studio, «Complete Beginner's Tutorial») получен **полный текстовый транскрипт** через web_reader. Для других популярных туториалов (Busy Works Beats, In The Mix) доступны были только заголовки, описания и списки глав — их содержание в выводы **не** включалось (честная сводка — в `sources.md`).
3. **Письменные туториалы и гайды** (EDMProd, mastering.com, Production Den и др.) — для проверки типовых end-to-end сценариев.
4. **Фиксация с уровнями уверенности.** Каждое существенное наблюдение помечено:
   - **[A]** — подтверждено официальным мануалом Image-Line (или официальным PDF/транскриптом);
   - **[B]** — подтверждено сторонним источником (статья/гайд/форум);
   - **[C]** — вывод/обобщение исследователя (не подтверждено прямым текстом источника).
   - «не найдено» — специально отмеченные пробелы, чтобы никто не принял отсутствие данных за факт.

## 4. Ключевые выводы (TL;DR)

1. **«Рабочий стол из плавающих окон».** FL Studio — не единое окно с вкладками, а набор независимых, перекрывающихся, «прилипающих» окон (Playlist F5, Channel Rack F6, Piano Roll F7, Mixer F9, Browser Alt+F8), которыми управляют функциональные клавиши-toggle и пресеты раскладки [A]. Это фундаментальное отличие от большинства DAW и главная проектная развилка для VibeStudio.
2. **Паттерн — центральная сущность.** Паттерн = все ноты/шаги/событийная автоматизация **всех** каналов Channel Rack на данном номере (до 999 паттернов). Все паттерны играют через **один и тот же** набор инструментов — паттерн не привязан к инструменту, как в большинстве секвенсоров [A]. Piano Roll и Step Sequencer — два вида одних и тех же нотных данных канала внутри паттерна.
3. **Playlist «не разбирает» клипы.** Треки плейлиста по умолчанию не привязаны ни к инструменту, ни к типу клипа, ни к треку микшера: Pattern/Audio/Automation Clips можно класть куда угодно и накладывать; звук определяет маршрутизация Channel Rack → Mixer, а не трек плейлиста [A]. (Опциональные «Track Modes» позволяют жёстко связать трек с аудио или инструментом.)
4. **Дуальность автоматизации.** Событийная (event) автоматизация живёт внутри паттерна и записывается «по-живому»; Automation Clip — отдельный канал-генератор в Playlist, который нельзя записать, но удобно рисовать. Между ними есть конвертация [A].
5. **Скорость через контекст.** Практически каждый элемент имеет: левый клик (основное действие), правый клик (контекстное меню), средний клик/модификаторы (Alt — обход snap, Shift — варианты, Ctrl — выделение). Hint Bar постоянно обучает пользователя (описание + горячая клавиша + индикатор «красная точка = параметр автоматизируем») [A].
6. **Микшер отделён от аранжировки.** Канал имеет ровно одно назначение mixer-трека; маршрутизация между треками — кликами по send-переключателям; sidechain — тот же send с нулевым уровнем; отдельного класса «send-треков» нет [A].
7. **Слайды/портаменто — только для нативных плагинов** (через внутренний механизм слайд-нот); для VST предлагается автоматизация pitch [A]. Это пример «натянутого поверх стандарта» собственного протокола — важный прецедент для собственного дизайна.

## 5. Ограничения и непроверенное

- **Видео-поведение «в динамике»** (анимации, отзывчивость, тайминги) не проверялось — только статическое поведение по документации и текстовым расшифровкам.
- Дефолтный темп нового проекта (**130 BPM**) и состав дефолтного шаблона (каналы Kick/Clap/Hat/Snare) подтверждены только сторонними источниками [B] — в прочитанных страницах мануала явных значений нет.
- Число треков Playlist в мануале не названо; исторические значения микшера расходятся (103 → 125 → 500) — актуальная цифра 500 insert [A].
- Некоторые хоткеи имеют расхождения внутри самого мануала (например, Quick quantize в плейлисте: Ctrl+Q vs Shift+Q) — отмечено в `behavior-catalog.md`.
- macOS-специфика дана только там, где её прямо упоминает мануал (Alt=Opt, Ctrl=Cmd).

## 6. Как читать документы

Все документы следуют принципу: **Уровень A** — наблюдаемое поведение FL Studio (факты с пометками уверенности), **Уровень B** — независимые спецификации для собственной реализации (как воспроизвести аналогичное поведение, не копируя ресурсы и брендинг). Блоки Уровня B выделены как «Спецификация для собственной реализации».
