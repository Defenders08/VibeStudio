# interaction-model.md — Модель взаимодействия окон и компонентов FL Studio

Уровень A (наблюдаемая логика) + блоки Уровень B (спецификация для собственной реализации). Пометки: **[A]** официальный источник, **[B]** сторонний, **[C]** вывод.

---

## 1. Главная ось: Каналы → Паттерны → Клипы → Песня

Наблюдаемая цепочка данных [A]:

```
Каналы (инструменты)  — единый набор для всего проекта
   ▲                │ звук
   │ ноты/шаги/     ▼
   │ события      Mixer-граф → Master → выход
ПАТТЕРН (все каналы)  ×999
   │ размещается как
   ▼
Pattern Clip в Playlist  +  Audio Clips  +  Automation Clips
   │
   ▼
Аранжировка (Song) — то, что играет в SONG mode и рендерится
```

Ключевые наблюдаемые правила:

1. **Паттерн не принадлежит инструменту.** «Все паттерны играют через один и тот же набор инструментов» — канал один, данных в нём много (по слою на паттерн) [A]. Смена номера паттерна мгновенно меняет содержимое Channel Rack [A].
2. **Piano Roll и Step Sequencer — две проекции одних данных.** Открытие Piano Roll по каналу показывает шаги как ноты на C5; обратная конвертация — Discard note lengths (Shift+D) [A]. Интерфейс rack сам переключает клетку шагов на «мини-ролл», когда в канале ролл-данные [A].
3. **Playlist — исполнитель инструкций.** «Когда playhead достигает клипа, FL Studio играет то, что клип инструктирует: ноты, аудио или автоматизацию» [A]. Трек плейлиста при этом — просто строка-слот: он не задаёт ни инструмент, ни микшер-трек [A]; звук определяет Channel→Mixer routing [A].
4. **Клип = окно над источником.** Аудио/автоматизация-клипы можно укорачивать/растягивать без потери данных за границами; для независимой копии — Make unique [A]. У Pattern Clip укороченный вид просто скрывает хвост паттерна [A/C].

## 2. Режимы воспроизведения и «кто главный»

- **PAT mode**: играет текущий паттерн (циклически) — режим «сборки». **SONG mode**: играет Playlist — режим «прослушивания/рендера» [A]. Переключение — клавиша L; правые клики по кнопкам PAT/SONG открывают Channel Rack/Playlist — режим и окно связаны семантически [A].
- Позиция в Song Position LCD следует за окном-контекстом (Playlist в SONG, Piano Roll в PAT) [A].
- **Зацикливание** определяется данными, а не транспортной кнопкой: маркеры Loop/Skip/Pause и выделение области времени [A].
- Запись MIDI в SONG mode автоматически вставляет Pattern Clip в позицию старта; в PAT mode — пишет в текущий паттерн [A].

**Уровень B.** Два режима — это два «VIEW поверх одного транспорта», а не два движка. Собственная спецификация: транспорт единый; `playScope ∈ {pattern, song, selection}`; контекст фокуса определяет, чья шкала времени отображается; запись определяет «цель по умолчанию» из scope.

## 3. Связи между окнами

| Пара | Наблюдаемая связь |
|---|---|
| Channel Rack ↔ Piano Roll | Piano Roll редактирует **Target Channel** текущего паттерна; переключение каналов в ролле — dropdown/колесо/G-H-J-K; ghost notes показывают остальные каналы паттерна [A] |
| Channel Rack ↔ Playlist | Паттерн из rack ставится клипом (Picker Panel / draw); Alt+двойной клик по Pattern Clip открывает rack на этом паттерне; Shift+колесо в rack листает паттерны [A] |
| Playlist ↔ Piano Roll | Двойной клик по Pattern Clip → Piano Roll этого паттерна (поведение «Edit patterns in» настраивается) [A] |
| Channel Rack ↔ Mixer | У канала один mixer-назначение (селектор в rack и в Channel Settings); Ctrl+L — расселить выбранные каналы по свободным трекам; drop инструмента на mixer-трек — создать канал с авторутингом [A] |
| Browser ↔ всё | Единый drag-источник: сэмпл → rack (Sampler) / Playlist (Audio Clip) / микшер (инструмент); плагин → rack/FX-слот; проект → рабочий стол [A] |
| Mixer ↔ Edison | Edison живёт в FX-слоте; Current-трек существует как «служебный» хост инструментов записи/анализа [A] |
| Параметры ↔ Playlist | Любой автоматизируемый параметр: ПКМ → Create automation clip (клип появится в Playlist); параметры проекта видны в Browser > Current project [A] |
| Undo ↔ Browser | История отмен — browsable папка Current project > History; клик по шагу = откат [A] |

## 4. Фокус, контекст и «одиночные клавиши»

- Одиночные буквенные клавиши (P, B, C, D…) работают как команды **активного окна**; когда включён Typing keyboard to piano (Ctrl+T), они переходят к вводу нот — мануал прямо предупреждает об этой взаимной исключительности [A].
- Инструменты редактирования (Draw/Paint/Delete/…) — **общий паттерн во всех редакторах** с одинаковыми буквами: P/B/D/T/S/C/E/Y/Z в Playlist и Piano Roll означают одно и то же [A]. Это переносимый навык между окнами.
- **Esc** закрывает окно; F-клавиши — toggle окон; Tab — цикл окон [A].
- При «Auto select linked modules» открытие одного плагина закрывает предыдущий — UI держит минимум открытых GUI [A].

## 5. Система жестов мышью (наблюдаемая грамматика) [A]

| Жест | Смысловое значение (унифицировано по программе) |
|---|---|
| ЛКМ | основное действие: поставить/включить/выбрать/открыть |
| ЛКМ-drag | непрерывное действие: рисование/перемещение/значение параметра |
| ПКМ | удалить / контекстное меню (смысл зависит от зоны: на данных — часто «удалить», на контроле — меню) |
| ПКМ-drag | удаление серией |
| Средняя кнопка | панорамирование вида (2D-скролл); в Browser — «загрузить в выбранный канал» |
| Двойной ЛКМ | свойства/открыть редактор |
| **Alt** | обход snap (временный) / отмена прилипания окон / альтернативное действие |
| **Shift** | вариант действия: копия, кисть, добавление к выделению, диагональный slice |
| **Ctrl** | выделение / точная подстройка (Ctrl+drag у крутилок) |
| Колесо | скролл; над контролом — значение; Shift+колесо — горизонталь/порядок; Alt+колесо — свойство ноты |
| ПКМ по крутилке | меню параметра: Type in value, Reset, Create automation clip, Link to controller, Edit events |
| Крутилки/фейдеры | вертикальный драг; Ctrl — тонко; Shift — игнор стопов; Alt+ЛКМ — сброс в дефолт; двойной инкремент у краёв LCD [A] |

**Уровень B.** Зафиксировать грамматику как единую таблицу «жест × контекст» в spec UI и прогонять её через все редакторы: любое исключение — осознанное проектное решение, а не случайность. Alt = «ослабить ограничения» (snap, docking), Shift = «вариант/множитель», Ctrl = «выделение/точность».

## 6. Контракт параметра (крутилка/слайдер)

Каждый редактируемый параметр в FL Studio имеет наблюдаемый набор возможностей [A]:

1. подсказку (hint) с описанием и значением;
2. правый клик: Type in value, Reset (Alt+клик тоже), Copy value (в hint), **Create automation clip**, **Link to controller**, Edit events / Init song with this position;
3. признак «записываемости» (красная точка в hint bar) и «линкуемости» (MIDI-иконка);
4. вхождение в Last tweaked (для ADD > Automation from last tweaked);
5. появление в Browser > Current project > Generators/Effects in use.

**Уровень B.** Ввести тип `AutomatableParam {range, default, unit, flags(recordable, linkable), tweak-history}` и единое контекстное меню параметра — это «скелет», который делает автоматизацию и MIDI-линкинг системными, а не ad-hoc.

## 7. Undo и «безопасность»

- Двухуровневый undo: Ctrl+Z (умный, вперёд/назад) и Ctrl+Alt+Z (пошаговый назад по истории); история доступна как папка в Browser (клик = прыжок по состояниям) [A].
- Опция Undo knob tweaks — твики параметров участвуют в истории [A].
- Автобэкапы + File > Revert to last backup; Save new version (Ctrl+N) создаёт MyProj_2/_3 [A].
- Отмена записи нот — Score logger: **всегда включённый** 3-минутный буфер всего ввода; «Dump score log to selected pattern» спасает сыгранное без записи [A].

**Уровень B.** Undo как журнал событий сBrowsable-историей; «постоянный логгер ввода» — дешёвая страховка, радикально снижающая страх потери импровизации.

## 8. Обучение пользователя встроено в интерфейс

- Hint Bar объясняет всё, на что наведён курсор, показывает хоткей и флаги автоматизируемости [A].
- Интерактивные уроки (Tutorials), Loop Starter в Channel Rack, demo-проекты в Browser (NewStuff.flp) [A/PDF].
- Опция «Autonomous»-подсказок: предупреждения (sad face, attention) при ошибках/latency [A].

**Уровень B.** Рассматривать hint-систему и demo-контент как часть архитектуры: каждая команда/контрол декларирует описание и хоткей; UI обязан их показывать. Это дешевле документации и формирует «скорость от мозга к звуку».

## 9. Многозадачность и многооконность

- Рабочие области: пресеты раскладок (Desktop/Tablet/Custom), Detach на второй монитор, прилипание окон [A].
- Performance Mode превращает начало Playlist в live-сетку клипов (триггер с мыши/клавиатуры/контроллера) — тот же документ, другой режим воспроизведения [A].
- Arrangements — несколько аранжировок на одном наборе каналов (варианты песни без копирования проекта) [A].

## 10. Хранение проекта

- **.flp** — только «ссылочный» проект: сэмплы и пресеты не встраиваются [A].
- **Zipped loop package** — .flp + все сэмплы в .zip (для переноса/шаринга) [A].
- **Project bones** — пресеты/скоры/автоматизация без сэмпла; **Project data files** — сбор всех использованных файлов в одну папку [A/PDF].
- Project data folder — опциональное хранение данных рядом с проектом [A].
- Demo-плагины сохраняются в проект с предупреждением; при открытии без лицензии заменяются заглушками [A].

**Уровень B.** Формат проекта разделить на «логический документ» (ссылки на ресурсы) и «упаковку» (архив для переноса) — это разные сценарии и разные кнопки Save. Версионирование (Save new version) и бэкап — первоклассные команды, а не настройки.
